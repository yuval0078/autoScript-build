# Current Analyzer CSV contract

This document describes the CSV written by `analyzer_refactored.py` without normalizing it into a different data model.

## Column order

The file begins with these twenty-one columns, in this exact order:

1. `Exp Step`
2. `Experiment`
3. `Experiment ID`
4. `Block`
5. `Block ID`
6. `Block Index`
7. `Block Count`
8. `Session ID`
9. `Participant`
10. `Age`
11. `Gender`
12. `Word`
13. `Group`
14. `Cell`
15. `Correct`
16. `Written Word`
17. `Reading End`
18. `Writing Start`
19. `Writing End`
20. `Strokes`
21. `Avg Interval`

For every position from `1` through the maximum target-word length in the loaded data, the exporter adds:

1. `Written Letter N`
2. `Letter N Start`
3. `Letter N End`

The final column is always `Screenshot File`.

## Consequences for ingestion

- The width of the CSV is not fixed across exports.
- An importer must locate the first twenty-one columns by their exact names.
- Letter columns must be detected by the repeated naming pattern rather than by a fixed maximum.
- `Screenshot File` must be read after all generated letter columns.
- The CSV should be stored as an artifact unchanged. Searchable database fields can be extracted during ingestion without rewriting the source CSV.

## Current value conventions

- `Correct` is exported as `True`, `False`, or an empty value.
- Missing age or gender values are written as empty cells.
- Timing values are formatted text generated by the Analyzer.
- `Screenshot File` may be empty when screenshots are not exported.
- Cloud finalization validates the Experiment, Block, Session, and participant
  identity columns against the immutable Run results. Older locally exported
  CSV files remain downloadable but are not accepted as a new atomic cloud
  finalization unless they use the current identity-bearing layout.
